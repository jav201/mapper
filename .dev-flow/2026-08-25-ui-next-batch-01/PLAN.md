## 8 · Risks and watch-items

| # | Risk | Mitigation |
|---|---|---|
| R1 | **The prototype is an SVG.** Focus traversal, key routing and the `Input` vs screen-binding conflict are unverified in Textual. | Every AT drives real keys (C-16). Expect Textual focus surprises inside the inspector; budget for them. |
| R2 | Editing widgets steal keys from screen bindings — typing `j` in a field must not navigate the map. | The inspector's edit surfaces are real `Input`s; the screen's single-letter bindings must not fire while one has focus. An explicit AT covers it. |
| R3 | **File-derived text into a Rich render path** (titles, notes, field values, attachment captions from `_nodos.yml`). | Construct every inspector line with `Text.assemble` + explicit styles or `rich.markup.escape`; hostile-input AT. |
| R4 | `mapper/osopen.py` hands a file-derived path to an OS handler. | No shell. Allow only `url`/`file` kinds; URLs restricted to `http`/`https`; `security-reviewer` gates it. |
| R5 | Removing `LayeredRenderer`'s ficha strip could orphan an assertion. | Reverse census (C-26) over the strip's strings across `tests/` before deleting. |
| R6 | Moving undo to app level changes ownership of `_snapshots` — a per-map stack keyed by `map_id` is needed, not one global stack. | Design it as `dict[map_id, list[snapshot]]`; AT: leave the map, come back, undo still works. |
