## 2. Answers to the seven questions

### Q1 — Are the thresholds falsifiable?

**`AT-056`, clause 1** (*"the rendered content occupies ≤ `h` physical rows at the width
`_canvas_size()` returns"*) — falsifiable, but **against the wrong comparand**, and this is the
review's central finding.

`h` is not the number of rows the canvas displays. `h` is the **renderer's row budget**:
`_canvas_size` returns `region.height − header_rows(...)`, where `header_rows` measures the
**layered** header's physical height (`app.py:1465` docstring: *"`render` emits `1 + (h - 1)`
LOGICAL lines and the widget spends `rows` PHYSICAL rows on the first of them"*). At `35x14`,
`region.height = 3` and `h = 2`. The row's **Statement** says *"the number of rows the canvas will
actually display"* — that is 3. The row's **threshold** says `≤ h` — that is 2. **The Statement and
the threshold are in different units, in the same row.**

This is `02j`'s rule one level in. The row correctly stopped conflating renderer width with terminal
width — and then kept conflating the renderer's row budget with displayed rows. The batch's
cautionary exhibit repeats itself inside its own correction.

Consequence, both directions:
- Keyed to `h`, the arm **fails pre-fix at `35x14` on something the operator cannot see** (3 rows
  painted, 3 rows shown), and the "fix" that satisfies it is to cut to `lines[:1]` — which would
  paint *one line fewer* than the screen can display. The threshold would drive a regression.
- Keyed to the frame, the arm **passes pre-fix at `35x14`** — `lost = 0`, measured.

Either way, at the row's own driven size the threshold does not measure the defect.

**`AT-056`, clause 2** (*declared hidden count == nodes whose full title is absent from the painted
frame*) — falsifiable and frame-side, which is right. Two problems, both in §3.

**`AT-057`** — **not falsifiable as written.** Named scenario, measured, not hypothetical: outline
at `(35,14)`, 7 of 8 nodes hidden, canvas header silent, strip silent. *"the count painted in the
renderer's header equals the count painted in the strip … Zero disagreements"* — zero
disagreements. **Green.** The defect `B-60` describes ships intact underneath it.

### Q2 — Are they vacuous-safe? (`C-55`)

**`AT-056`: no, and it is worse than the degenerate-fixture case you flagged.** The fixture question
turns out not to bite here — at `35x2` on `legacy`, 7 of 8 are hidden — but the row **names no
fixture at all**, which every sibling does (`HLR-N06.3` pins `legacy` with a four-row `(w,h,folded)`
table and proves the seed map non-viable; `LLR-N06.3.2` ships `anidado` normatively;
`LLR-N06.3.3` names M-1's 6-node graph). A row with no fixture is a row whose arm can be passed or
failed by the implementer's choice of input.

The live vacuity is the other end. **`lines[:0]` passes `AT-056` as written.** Paint nothing:
- clause 1: 0 physical rows `≤ h`. ✔
- clause 2: declare all 8 hidden; all 8 titles are absent from an empty frame; `8 == 8`. ✔

That is `MUT-1` from `HLR-N06.3`'s own mutation table — *"a renderer that declares nothing painted
passes the batch's headline predicate"* — reappearing one renderer over. The row needs a
**maximality** clause: the cut must be the largest that fits, not merely one that fits. `PHYS-2` in
§3.

**`AT-057`: no.** `(80,24)` on `legacy` in outline hides **0** nodes (measured). Both surfaces are

either.

### Q3 — Is the oracle independent of the implementation? (`C-31`)

**`AT-056` clause 2 is independent as phrased** — *"absent from the painted frame"* is a frame read,
not a `painted_ids` read. Keep that. The danger is in the implementation of the arm, so the row must
forbid the shortcut in words: the hidden set is derived from the **composited region rows**, never
from `painted_ids(...)`, never from `len(graph.nodes) - len(painted)`. If the arm computes the
oracle the way the product computes the declaration, it asserts an identity between a value and
itself — `HLR-N06.3` already records this as `PRED-1`'s structural weakness and `M-N06.3-b` as the
layout-map version of it.

**But the predicate itself is borrowed from the wrong geometry.** *"full title"* is the reading
`HLR-N06.3` **superseded**: §A-21 measures a full/long-prefix trace false-failing **69 of 129**
unpainted node-observations, and settles the normative predicate as *"`_clip(plain(title),
card_w - 3)` restricted to the visible columns"*. That predicate is `layered`'s **card** geometry —
`card_w` does not exist in outline. `02m` §7.3 is explicit that this must not be papered over:
*"`B-55` ships three different definitions of painted behind one operator-facing numeral … the
predicate be named and stated per module."*

So outline's predicate must be **stated in this row**, not inherited. I measured which reading is
sound for outline: outline paints titles **unclipped and word-wraps** rather than truncating, so the
title survives whole across a wrap. Over 8 sizes on `legacy` (`w = 20, 22, 24, 26, 28, 30, 32`, two
heights), the per-row read and the wrapped-join read **agree at 8 of 8**. The join rule costs
nothing and protects against a title that splits at a space, so state the joined form.

### Q4 — `AT-056` drives `35x14`. Is one reachable size enough?

**Wrong size, and no — one is not enough.**

Wrong size: §1.1. `35x14` loses nothing.

Not enough: with a single clipping size and no control, a "fix" that clips **everywhere** is green.
Concretely, `lines[:max(0, h - 2)]` would pass a single-size arm, satisfy clause 1 everywhere, keep
clause 2 consistent (it declares what it hid), and quietly amputate one line of content at **every**
terminal the operator uses. Only the sizes where outline currently fits can catch that — which is
precisely your "negative control" instinct, and it is correct.

**Recommended driven set (§3): three clipping sizes + two negative controls**, all `legacy`, outline,
terminal sizes driven through `run_test`:

| terminal | role | why this one |
|---|---|---|
| `(30, 16)` | clipping | verified loss: `    - Contabilidad` emitted, absent from the frame |
| `(32, 16)` | clipping | verified loss, **and already driven by this batch** (`test_overflow.py:567`) |
| `(24, 20)` | clipping | verified loss deeper in the tree: `  - RRHH  2 nodos`; different logical index, so an off-by-one fix cannot pass all three |
| `(50, 16)` | control | nothing lost, **5 of 8 still hidden** — the declaration must be right where the cut is not the cause |
| `(80, 24)` | control | nothing lost, **0 hidden** — `LLR-N06.3.3`'s zero form |

Two controls, not one, because they control different things: `(50,16)` says *don't over-cut*,
`(80,24)` says *don't declare at zero*.

### Q5 — `AT-057`: is "equal counts" sufficient?

No, on both failure modes you named, and the first is not hypothetical.

  construction; agreement between a value and a copy of itself is not a measurement. Fixed by

Also unquantified: *"every view that declares"*. At `Inc-B55a`'s gate that set is
`{layered, outline}`; `radial` joins at `Inc-B55b`. Left as prose, the arm's coverage is whatever
the implementer parametrised. Derive the set at run time from `painted_ids_exporters()`

the same tripwire idiom `test_a98_*` already uses.

> ##### `LLR-N06.3.6` — a declaration that BROKE is not a view that declares nothing
>
> - **Traceability:** `HLR-N06.3`

> - **Statement:** While the declaration for the current view cannot be computed, the system shall
